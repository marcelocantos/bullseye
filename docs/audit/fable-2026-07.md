## Architecture

Bullseye is a Rust MCP server (binary `bullseye`) managing **targets** — desired project states expressed as testable properties — persisted as YAML.

**Entry point** (`src/main.rs`): parses argv. No args → start stdio MCP server (rust-mcp-sdk + tokio). Subcommands `sync-priorities` (→ `priorities.rs`) and `github sync` (→ `github.rs`) are CLI twins of MCP tools. `AGENTS.md` declares **surface parity**: every capability reachable from both MCP tools and CLI, sharing one entry point.

**Core modules:**

- **`schema.rs`** — data model. `TargetsFile { schema_version: Option<u32>, last_evaluated, targets: BTreeMap<String,Target> }`. `Target { name, status, value/cost f64, acceptance Vec<String>, depends_on, cross_depends/cross_enables, tags, strategy, origin, discovered/achieved dates, set_aside_reason }`. `Status` enum `{Identified, Converging, Achieved, SetAside}`; `CURRENT_SCHEMA_VERSION = 5`. Legacy `gates` edges folded into `depends_on` on load via `migrate_gates_to_depends_on`.
- **`store.rs`** — YAML I/O + concurrency. `discover_anywhere`: in-repo walk-up from cwd (`MAX_DEPTH 64`), else external shadow tree under `~/.local/share/bullseye` mirroring absolute cwd. Process-global mtime-keyed parse cache (`std::sync::Mutex`, no I/O under lock; serves stale copy on soft parse error, always propagates `VersionTooNew`). `save()`: atomic tempfile + fsync + rename with regenerated `FILE_HEADER` banner, evicts cache. `with_locked_mutation()`: flock on a lockfile under `temp_dir` keyed by parent-dir `(dev,ino)` → fresh re-parse (bypasses cache) → closure → CAS re-stat `(mtime,len)` → atomic save. `with_locked_write` for wholesale import.
- **`graph.rs`** — pure graph logic. `frontier()` = active targets whose every `depends_on` resolves to a terminal target. `validate_blocking()` = dup IDs, negative value/cost, empty acceptance, dangling `depends_on`, cross-edge shape, `set_aside_reason` presence rules, strategy non-empty, DFS cycle detection, zero-dotted-segment ID ban. `validate_warnings()` = advisory ID-format check. `rank_frontier()` by unblocking fanout then ID. `summary()`/`startup_context()` renderers.
- **`handler.rs`** — MCP dispatch (`TargetHandler::handle_call_tool_request` routes 20 tools). Mutating handlers: discover_path → `ensure_mutation_allowed` (repo_guard) → per-field write-boundary guards (envelope-leak markers, invalid control chars, zero-dotted-ID) → `with_locked_mutation` closure → `git_commit::auto_commit_yaml`. Read handlers bypass guard/lock and tolerate broken files.
- **`ops.rs`** — domain ops shared by handlers: revert (Achieved→Converging, clears date, appends reason to context), subdivide (Add/Aggregate/Retire modes rewiring dependents), verify_plan (emits sawmill check plan; bullseye never calls sawmill directly), next_subtarget_id.
- **`repo_guard.rs`** — `check_mutation_allowed` refuses mutations when the repo containing `bullseye.yaml` is a submodule or on detached HEAD (auto-commit would land on an orphan branch). Non-git dirs pass.
- **`git_commit.rs`** — best-effort `auto_commit_yaml`: adds/commits only `bullseye.yaml`; amends prior commit iff it is unpushed AND touched only `bullseye.yaml`; else new commit. Failures logged, never propagated.
- **`id_alloc.rs`** — `historical_ids` scans `git log -p --all --remotes` for every `T<N>` key ever added (never recycled), memoised per repo-top; empty for non-git/external mode.
- **`config.rs`** — `Location {InRepo, External}`; `external_root()` precedence: thread-local test override → `BULLSEYE_DATA_DIR` → `$HOME/.local/share/bullseye`. `expand_tilde`.
- **`resolve.rs`** — maps repo reference (leaf/org-repo/path/absolute) to a repo root by suffix-match over a cached workspace scan; ambiguity surfaced, never silently resolved.
- **`portfolio.rs`** — cross-repo discovery, WSJF-style portfolio ranking (value/cost consumed only at portfolio scope). **`priorities.rs`** — sync frontier into a SQLite table (rusqlite). **`github.rs`** — two-way GitHub issue⇔target mirror shelling out to `gh`.

**Data flow:** every MCP tool call carries a `cwd` param → `store::discover_anywhere` finds `bullseye.yaml` → load/parse → operation → save.

## Invariants

1. **Atomic durable write** — `save()` must write via a same-directory tempfile that is fsync'd then renamed into place, so a reader or crash never observes a half-written `bullseye.yaml` (cross-filesystem rename would break atomicity — tempfile must be a sibling).
2. **Serialized read-modify-write** — every mutation must run inside `with_locked_mutation`, which (a) holds an exclusive flock, (b) re-parses fresh from disk bypassing the cache, and (c) aborts with Conflict if the file's `(mtime,len)` changed between read and write — preventing lost updates from concurrent bullseye processes or non-flock-aware editors.
3. **Lock identity** — the lockfile key is the project parent directory's `(dev,ino)` pair, so all access paths to one project (symlinks, atomic-rename inode churn of the yaml, dir renames) map to the same lock, and distinct projects never share a lock.
4. **Schema-version gate** — a file whose declared `schema_version` exceeds `CURRENT_SCHEMA_VERSION` must always fail loud (`LoadError::VersionTooNew`) and never be served from cache, so a newer file is never silently misinterpreted by an older binary; every save stamps `schema_version = CURRENT_SCHEMA_VERSION`.
5. **Graph well-formedness** — `depends_on` graph must be acyclic and referentially closed for graph operations; `validate_blocking` must detect cycles (DFS) and dangling `depends_on` before frontier/convergence/portfolio consume the graph, and any blocking error suppresses frontier output rather than emitting a meaningless recommendation.
6. **Frontier correctness** — a target is in the frontier iff it is active (non-terminal) and every `depends_on` ID resolves to a terminal (Achieved or SetAside) target; both Achieved and SetAside must unblock dependents identically.
7. **Terminal-status semantics** — `Status::is_terminal()` must include exactly `{Achieved, SetAside}`; `achieved()` counts only Achieved, so set-aside targets never inflate the achievement record.
8. **set_aside_reason integrity** — a non-empty (non-whitespace) reason is required exactly when `status == SetAside` and must be absent otherwise; set_aside is settable only via `bullseye_set_aside` (not `bullseye_put`) so the rationale is always recorded with the status change.
9. **Achieved immutability** — content edits to an Achieved target (including `depends_on` injection via `blocks` sugar) must be rejected unless the same call re-opens it to a non-achieved status; retirement dates and history are preserved.
10. **Global ID non-recycling** — auto-allocated target IDs must exceed every ID ever recorded in git history (`historical_ids`) as well as in-memory keys, and an explicit-id create that collides with a historical ID must be rejected — no two branches independently reuse an ID for different targets.
11. **Write-boundary content sanitation** — every caller-controlled persisted string must pass envelope-leak (tool-call XML markers) and invalid-control-char checks before entering the locked mutation, so malformed content never lands in `bullseye.yaml`; dotted IDs ending in `.0` are disallowed (T4 vs T4.0 ambiguity).
12. **Mutation safety guard** — mutating operations must be refused when the repo containing `bullseye.yaml` is a submodule clone or on detached HEAD, because auto-commit would strand the change on an unreachable branch; read-only ops and non-git/external storage bypass the guard.
13. **Auto-commit scoping** — `auto_commit_yaml` must stage and commit only `bullseye.yaml` (never other staged files) and may amend the prior commit only when that commit is unpushed AND touched solely `bullseye.yaml`, so a pushed or mixed commit is never rewritten.
14. **Banner idempotence** — the `FILE_HEADER` banner is owned by `save()` and is never part of the parsed model, so it appears exactly once regardless of save/load cycles and never duplicates or drifts.
15. **External shadow-path containment** — `shadow_path` must strip root/prefix/curdir/parentdir components so a cwd can never escape upward out of `external_root`; `discover_external` stops at root.
16. **Repo-vs-portfolio scope separation** — value/cost/momentum must not influence repo-level frontier ordering (fanout + ID only); they feed only portfolio-scope WSJF ranking.

## Trust boundaries

1. **MCP tool-call parameters** (`handler.rs handle_call_tool_request`): all fields including `cwd`, ids, names, acceptance, reasons arrive from the agent/LLM and are untrusted. `cwd` drives filesystem discovery; string fields are persisted. Guarded by envelope/control-char/zero-ID checks — but numeric value/cost and `depends_on` references are only shape-validated.
2. **`bullseye.yaml` file content on disk** (`store::parse_file` via serde_yaml_ng): the file is hand-editable and may be written by other tools/branches/older binaries. Untrusted for structure (version gate, migration) and for semantic validity (`validate_blocking` runs downstream, not at parse time).
3. **Filesystem paths and the external shadow tree**: caller `cwd` and `workspace_root` are joined into paths (`shadow_path`, discover walk-up, resolve absolute passthrough). Path traversal / symlink resolution is the boundary; `canonicalize` is used for lock keys and pathspec stripping.
4. **Environment variables**: `HOME`, `BULLSEYE_DATA_DIR`, `TMPDIR`/`temp_dir` determine external storage root and lock root; a hostile or misconfigured environment redirects where targets and locks live (HOME has a hardcoded `/Users/marcelo` fallback).
5. **Git subprocess boundary** (`id_alloc.rs`, `git_commit.rs`, `repo_guard.rs`): shells out to `git -C <dir> ...`; stdout is parsed (rev-parse, log -p, symbolic-ref, rev-list). Repo state (branches, remotes, superproject, detached HEAD, hooks) is external input that steers ID allocation and commit behavior; failures are swallowed to best-effort no-ops.
6. **GitHub `gh` CLI boundary** (`github.rs RealGh`): issue titles/bodies/labels/state from `gh issue list --json` (`GhIssueJson`) are deserialized and mirrored into target fields — untrusted remote content crossing into persisted YAML via the sync path.
7. **Markdown import source** (`handler.rs handle_import` → `import::parse_markdown`): an arbitrary caller-specified file path is read and bulk-parsed into targets; every parsed target string is re-checked for envelope leaks before persistence, and the result is validated before write.
8. **SQLite output sink** (`priorities.rs sync-priorities`): writes the portfolio frontier into a caller-specified `--db` path via rusqlite; the db path and table are an out-of-process surface the CLI/MCP twin populate.
